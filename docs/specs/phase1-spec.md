## 1. 概述

### 1.1 目标

为 Monitor ERP 项目实施建立**多租户 SaaS 平台**，让 Monitor ERP 内部员工（实施、开发、售后支持、市场、销售、超管）与外部客户（项目经理、Key User、普通用户）在**一个平台上**协作完成实施项目的管理：客户资料、蓝图、实施阶段、会议纪要、问题清单，以及基于知识库的客服 AI Agent 与客户操作手册自动生成。

### 1.2 范围（Phase 1 包含）

| 域 | 内容 |
|---|---|
| 用户与身份 | 平台自建账号、角色、认证、用户管理 |
| 项目管理 | 客户基础资料、蓝图（版本化）、实施阶段/状态/风险、会议纪要、问题清单 |
| 知识库 | 内部知识库（在线文档/上传文件/Online help 导入）、客户知识库、发布即同步 RAG |
| AI | 内部客服 AI Agent、客户操作手册自动生成（文本） |
| 权限与隔离 | RBAC + 租户/项目边界 + 数据隔离红线 |

### 1.3 第二阶段边界（本 Spec 不覆盖，架构预留接缝）

- 会议视频信息提取（第三方）
- Monitor ERP 系统 API 集成
- 日历（甘特图）与邮箱同步
- 基于功能清单生成蓝图/风险清单
- 培训视频与学习平台（含视频生成）
- 客户侧 AI Agent
- 其他内部 AI Agent
- **客户基础数据导入工具**（用户明确"暂不讨论，仅记录"）

### 1.4 关键约束

1. **平台无关性**：不锁定阿里云。数据库用标准 PostgreSQL；对象存储用 S3 兼容抽象；消息队列可替换；RAG 平台经适配层可换（百炼为首选但非唯一）。
2. **规模**：大规模多租户（数千+客户），数据边界 = 项目。
3. **数据隔离是最高优先级**：客户 A 的数据与知识不得被客户 B 触达（详见 §7）。
4. **LLM 模型层抽象可切换**（主模型 + embedding）。

## 2. 用户与身份

### 2.1 用户类型与角色

| 类型 | 角色 | 说明 |
|---|---|---|
| 内部用户 | 实施 / 开发 / 售后支持 / 市场 / 销售 | Phase 1 **功能权限相同**（均可查看并维护所有客户数据，**可创建项目并归属到客户**），角色为组织标签 |
| 内部用户 | 超级管理员 | 内部全权限 + 平台管理（建客户/管账号/角色分配/系统配置） |
| 客户用户 | 项目经理 | 客户组织内角色，按项目授权 |
| 客户用户 | Key User | 同上 |
| 客户用户 | 普通用户 | 同上 |

- 客户与项目为 **1:N**：一个客户可有多个实施项目。**数据边界 = 项目**。
- 客户用户可跨项目，成员身份按项目分配（项目成员 = 用户 + 项目 + 角色）。

### 2.2 认证

- 平台自建账号体系，**邮箱 + 密码**。
- 客户用户：内部创建账号后走**邮箱邀请链接首次设置密码**。
- 内部用户：由超管创建。
- 会话：JWT Access Token + Refresh Token（Redis 存会话，支持下线/互斥）。详细接入见技术架构（§8）。

### 2.3 用户管理

- 内部（超管/内部用户）：创建客户用户账号，分配项目成员身份与角色。
- 客户项目经理：可在**自己项目内**自助邀请/停用普通用户（Key User/普通用户）；不跨项目、不升级角色。
- 后续增强（非 Phase 1）：基于具体功能/页面/字段的可配置权限 + 用户组 + 默认值（记录，不在本 Spec 实现）。

### 2.4 权限矩阵（Phase 1）

| 功能 | 内部/超管 | 项目经理 | Key User | 普通用户 |
|---|---|---|---|---|
| 查看蓝图 / 实施阶段 / 会议纪要 | ✅ | ✅ | ✅ | ✅ |
| 问题清单 — 提交 | ✅ | ✅ | ✅ | ✅ |
| 问题清单 — 评论 | ✅ | ✅ | ✅ | — |
| 问题清单 — 修改/管理 | ✅ | ✅ | — | — |
| 客户资料 / 蓝图 / 阶段/风险 / 会议纪要维护、**创建项目（归属客户）** | ✅ | — | — | — |
| 知识库文档编辑 / 操作手册生成 | ✅ | — | — | — |
| 客服 AI Agent | ✅ | —（客户 Agent 属 Phase 2） | — | — |

## 3. 项目管理

### 3.1 客户基础资料

- 字段：名称、行业、地域，等（Phase 1 基础字段，可扩展）。
- 内部用户维护；客户用户只读（客户自身的资料由其项目的成员在授权范围内查看）。

### 3.2 蓝图

- **一个项目一份，带版本控制**。
- 版本内容：**draw.io 流程图 + 结构化文档**（业务需求、模块/功能范围、配置说明、流程描述）。
- draw.io 文件存对象存储（S3 兼容），结构化内容存数据库；版本为两者的一致性快照。
- 内部用户（实施）维护；客户用户只读查看。
- 关联：蓝图是操作手册生成的输入（§6）；可被问题条目关联（§3.5）。

### 3.3 实施阶段 / 状态 / 风险

- **实施阶段**：基于**标准阶段模板**，项目可增删/调整。阶段有状态（如 未开始/进行中/已完成/已暂停）。
- **风险点**：**项目级**，可**关联到具体阶段**。字段：描述、等级（高/中/低）、状态、负责人。

### 3.4 会议纪要

- 结构化字段（主题、日期、参会人等）+ **富文本正文** + **附件**（上传文件）。

### 3.5 问题清单

- **问题（Issue）**字段：标题、描述、类型、**分类**（功能/数据/使用/技术/优化）、优先级、提交人、指派人（内部）、状态（新建 → 处理中 → 已解决 → 已关闭）、评论。
- 可**关联蓝图/功能/文档**（便于追溯）。
- 客户提交、查看、修改、评论按权限矩阵（§2.4）执行。

## 4. 知识库

### 4.1 内部知识库

- **内容**：标准操作手册、FAQ、最佳实践、**Online help（外部项目提供，只读导入）**。
- **文档形态**：在线 **Markdown**（前端提供好用的 Markdown 编辑器）或**上传文件**（Word/Excel/PDF 等）。
- **分类**：操作手册 / FAQ / 最佳实践。
- **生命周期**：草稿 → 已发布 → 已归档；**版本化**。
- **在线编辑**：仅 Markdown（Phase 1）；文件类文档为上传 + 覆盖更新。

### 4.2 客户知识库

- 逻辑构成 = **内部知识库 + 该客户所有项目文档**，**不含其他客户**。
- 客户项目文档：蓝图、会议纪要、操作手册（含自动生成）、上传的知识库文档、问题解决沉淀条目。
- 物理实现见 §7.2 与架构图：**共享内部 Index + 每客户一个 Index**（文档按项目打标签）。

### 4.3 文档 → RAG 自动同步

- **触发模型：发布即同步（版本化）**——只有"已发布"进 RAG，草稿永不进；编辑已发布文档生成新草稿版本，重新发布才更新；归档从 RAG 删除。
- **事务入队**：发布 = 消息队列**事务消息**（"状态→已发布"与"同步事件入队"同一事务，入队失败则发布回滚）——保证"已发布"必有至少一次同步尝试。
- 同步 Worker 经 `DocumentIndexPort` 适配器异步导入、轮询状态、幂等（平台文档 ID + 版本号）。
- 失败：Worker 基本重试（指数退避）；超出记日志（告警/文档级同步状态为后续增强）。

### 4.4 Online help 导入

- 平台提供**导入 API** + **定时同步**：外部项目推送或平台定时拉取，**增量同步**，只读 → 内部 Index。
- 格式：Markdown / HTML / PDF / Word 等。

## 5. 内部客服 AI Agent

| 项 | 决定 |
|---|---|
| 构建方式 | **平台自研 Agent 编排（LangGraph.js）**；RAG 平台**仅提供检索**（经 `DocumentIndexPort` 适配，平台无关） |
| 编排框架 | **LangGraph.js**（TypeScript）：图节点 = 检索 / 生成 / 引用解析；State 含会话历史与检索范围；Checkpointer 持久化 |
| 对话入口 | 独立「AI 客服」页面 + 悬浮小组件 |
| 引用溯源 | 回答带引用角标，可点击跳转知识库文档原文/章节（自研实现） |
| 会话 | LangGraph.js checkpoint 持久化（数据库），多轮记忆，可回看/继续，可审计 |
| 检索范围 | **内部 KB + 所有客户 Index**（内部用户全量；后端注入范围） |
| 权限 | 仅内部用户可访问；客户 Agent 复用同一编排（Phase 2） |

实现要点：LLM 经 `LLMClient` 抽象门面；跨大量客户 Index 的检索用 RAG 平台的多库检索能力（多库联合检索/按相关性选库，经适配层）。内部 Agent 与客户 Agent（Phase 2）是**同一张 LangGraph.js 图**，仅检索范围不同（内部 = 全量；客户 = `[内部, 该客户]` + 项目过滤）。

## 6. 客户操作手册自动生成

- **输入**：蓝图（选版本：draw.io 流程图解析为流程文本 + 结构化文档）+ 客户基础资料/项目数据。
- **生成粒度**：**分章节生成**（按蓝图模块/业务功能），每章独立生成、可逐章审校/重生成；审校后组装成**一本完整手册**。
- **生成引擎**：平台 **LLM 抽象层**（可切换供应商），与 RAG 平台解耦。
- **触发**：**手动触发**（可选蓝图版本）+ 蓝图发布新版本时**提示**"蓝图已更新，建议重新生成"（不自动覆盖已审校内容）。
- **审校发布**：复用文档生命周期——生成结果存为项目知识库文档（草稿态，分类=操作手册），实施在 Markdown 编辑器逐章审校/修改，发布 → 走 §4.3 管线进该客户 Index。
- **产物归属**：项目文档（进客户 KB）；可选沉淀为内部标准操作手册。
- **视频生成**：Phase 2。

## 7. 权限与数据隔离

### 7.1 平台关系数据库（标准 PostgreSQL）

- 共享 schema，所有业务表带 `tenant_id`（客户级）。
- **客户级 RLS**：`USING (tenant_id = current_setting('app.tenant_id'))`；内部用户连接设 `app.is_internal=true`（可见全部）；客户用户连接设 `app.tenant_id = 该客户`。
- **项目边界靠应用层**：服务层校验用户的项目成员关系后放行（访问控制中间件）。
- 跨客户泄漏 = 数据库层直接拒绝（红线强制）。

### 7.2 客户 RAG 知识库（经 `DocumentIndexPort` 适配，平台无关）

```
内部 Index（共享，只存一份）── 标准操作手册 / FAQ / 最佳实践 / Online help
每客户 Index（1:1 客户） ──── 蓝图 / 会议纪要 / 操作手册 / 上传文档 / 问题沉淀
                              （文档按 project_id 打标签）

检索注入：后端注入 [内部 Index, 该客户 Index] + 项目标签过滤
客户用户仅命中授权项目的切片；内部用户经后端可访问全部
```

### 7.3 防泄漏红线（强制）

1. RAG 平台 **API Key 只存自有后端，绝不下发客户端**；客户端无法直接调用 RAG 平台 API。
2. 所有检索由后端注入 Index 范围与项目标签过滤。
3. 上线前做**跨客户检索渗透测试**（A 客户凭证仅能命中 A 的 Index）。
4. 审计日志记录检索与数据访问行为。
5. 平台数据库层 RLS 兜底（§7.1）。

## 8. 技术架构

### 8.1 技术栈

| 层 | 选型 | 备选 |
|---|---|---|
| 前端 | **Next.js + React + TypeScript + shadcn/ui**（Tailwind） | Ant Design / MUI |
| 后端 | **NestJS**（TypeScript，Fastify 适配器） | Fastify / Hono |
| 数据库 | 标准 **PostgreSQL**（共享 schema + `tenant_id` + RLS） | MySQL + 多租户拦截器 |
| ORM | **Drizzle**（schema 内原生 `pgPolicy` / `pgRole` 管理 RLS） | Prisma / TypeORM |
| 对象存储 | S3 兼容（OSS / MinIO）| — |
| 消息队列 | 可替换（RocketMQ 首选，事务消息） | Kafka / MNS |
| 缓存/会话 | Redis 兼容 | — |
| 鉴权 | NestJS + JWT + 租户域内 RBAC | — |
| LLM 抽象 | TypeScript OpenAI 兼容客户端门面（`LLMClient`，可切 Qwen/DeepSeek/GLM） | LangChain.js / LiteLLM |
| Agent 编排 | **LangGraph.js**（平台自研；RAG 平台仅检索） | 裸编排 / Vercel AI SDK |
| RAG 平台 | **平台无关**（候选 Dify / RagFlow / 阿里云百炼），经 `DocumentIndexPort` 适配 | 供应商后续决定 |
| 工程结构 | **Turborepo + pnpm workspaces**（monorepo：`apps/web` + `apps/api` + `packages/*` 共享类型） | Nx / 独立仓库 |

> 技术栈为**用户定稿**（2026-08-04）：**全栈 TypeScript**——前端 Next.js + React + shadcn/ui，后端 NestJS + Drizzle，monorepo 用 Turborepo + pnpm，Agent 编排 LangGraph.js。多租户 RLS 经 Drizzle schema 内 `pgPolicy`（`current_setting('app.tenant_id')`）实现。调研记录见 `research/tech-stack-typescript.md`。

### 8.2 系统组件（详见架构图）

- **接入**：ALB/API 网关 → 后端服务。
- **后端服务**（NestJS · TypeScript，模块化单体；ORM：Drizzle + drizzle-kit）：Auth & RBAC、项目管理（客户/蓝图/阶段/风险/纪要/问题）、知识库文档（创建/上传/导入）、操作手册生成引擎、客服 Agent（LangGraph.js 编排：范围注入/引用/会话 checkpoint）、同步 Worker。
- **数据**：PostgreSQL（RLS 多租户）、S3 兼容存储、Redis、消息队列。
- **外部**：RAG 平台（**仅检索**，适配层，供应商待定）、LLM Provider（抽象层）、Online help（外部项目）。

### 8.3 多租户与隔离

- 池模型（共享库）+ 客户级 RLS + 应用层项目边界（§7.1）。
- RAG 每客户一个 Index + 共享内部 Index + 项目标签（§7.2）。

### 8.4 事件驱动（文档 → RAG）

- 发布 → 事务消息 → 同步 Worker → `DocumentIndexPort`（导入/轮询/幂等/删除）→ 目标 Index 按文档 scope 路由。

### 8.5 LLM 抽象

- 平台侧 `LLMClient`（chat/embedding）门面，避免框架绑定；供操作手册生成等平台自有 AI 功能使用。RAG 平台的检索/Agent 内部模型与平台侧解耦。

## 9. 第二阶段预留接缝

- **Monitor ERP API 集成**：平台后端预留外部系统集成适配点（蓝图/风险清单数据的读写）。
- **视频生成**：操作手册生成管线预留"章节 → 视频"扩展（Phase 2）。
- **日历/甘特图/邮箱**：项目管理模块预留阶段/任务的时间维度扩展。
- **客户侧 AI Agent**：检索范围注入已支持"客户用户 → [内部 Index, 该客户 Index] + 项目过滤"，届时复用之。
- **数据导入工具**：预留"客户基础数据"导入接口（当前仅记录）。

## 10. 非功能需求

| 类别 | 要求 |
|---|---|
| 安全 | 邮箱+密码；JWT 会话；API Key 仅后端；RBAC + RLS；跨客户渗透测试 |
| 审计 | 检索、数据访问、权限变更日志 |
| 性能 | 数千+租户；池模型 + 索引优化；RAG 检索按相关性选库控制成本 |
| 可观测 | 日志、指标、链路追踪（如 Prometheus/SLS/ARMS 等价物，平台无关） |
| 合规 | 中国境内数据驻留；ICP 备案（若对外）；客户数据权限审计 |
| 成本 | RAG 每客户 Index 规格费随客户数线性（约 21.6 元/库/月），设计休眠/归档策略 |
